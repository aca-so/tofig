tofig rebuilds self-contained HTML as native Figma nodes — real frames, live text, editable vectors. Not a screenshot. Open it in a Design file and you get frames; open it in Slides and you get slides.

Three steps, no account

The plugin UI is a real browser. It renders your HTML in a hidden iframe, reads the computed styles and geometry, and rebuilds each element as a native node.

  1. Open tofig

    In a Figma Design file or a Figma Slides file. tofig reads figma.editorType and targets the right output automatically.

  2. Paste or drop

    Paste markup straight in, or drop a single .html file. Inline CSS, data: images and inline SVG all come along.

  3. Convert

    You get frames, text you can retype, vectors you can reshape, image fills, gradients, strokes and corner radii.

One plugin, two destinations

Where you run it decides what comes out. There's no mode to pick.

Design file

Frames on the canvas

Each captured root becomes its own frame, clipped to its bounds so an overflowing child stays inside the artboard instead of hanging behind it. A multi-section deck arrives as one frame per section.

Slides file

Real Figma slides

tofig detects decks — including JavaScript-driven ones — and imports each slide as its own Figma slide, sized and scaled to fit rather than clipped.

What survives the trip

And, just as importantly, what doesn't. These limits are real — knowing them up front is cheaper than discovering them at 2am.

Text stays text
Retype it, restyle it, rewrap it. Typography maps to the nearest available weight and style in your Figma fonts.
Inline SVG becomes vectors
Editable paths on the canvas, not a flattened raster.
Fills, gradients, strokes, radii
Rebuilt as native Figma paints and properties.
Missing fonts are substituted
If a font isn't in your Figma, text falls back to the nearest match, then Inter — and tofig reports exactly what changed.
Layout is absolutely positioned
Chosen for visual fidelity. Auto-layout is on the roadmap; today you get pixel-accurate placement, not responsive constraints.
External URLs are never fetched
The plugin declares networkAccess: none. Make your HTML self-contained: inline styles, data: images, inline SVG.

When an export won't render

Some files called "HTML" are really live apps. They boot a React runtime, pull React or Babel from a CDN, or reach for localStorage. Figma's plugin sandbox blocks all of that, so they can't render inside the plugin.

This is a sandbox limit, not a bug.

No network and a data:-URL origin are exactly what make the plugin safe to run on untrusted markup. The workaround keeps that property.

Render the file in a real, unrestricted Chrome on your own machine, then import the result. Same extractor, same output — just a browser without the sandbox. Drop the resulting .tofig.json into the plugin and it imports directly.

Requires a local Google Chrome or Chromium. Still fully local — nothing is uploaded.

# one-off, no install
npx --package=@aca-so/tofig tofig-render export.html

# or install it
npm install -g @aca-so/tofig
tofig-render export.html --target slides

Writes export.tofig.json next to the input. --package= is needed because the binary is named differently from the package.

Install tofig

The plugin is published to the acaso organization in Figma. The renderer is a separate, optional CLI.

Figma plugin

Open any Design or Slides file, then find tofig under your organization's plugins. Building from source works too — clone the repo, run npm run build, and import the manifest.
